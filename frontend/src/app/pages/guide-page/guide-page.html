Verificación de Demostraciones

La pestaña Validar Demostración permite comprobar si un fragmento de código Lean 4 es correcto. El sistema lo envía al servicio de verificación formal y devuelve el resultado junto con los mensajes del compilador.

1 Escribe o pega el código Lean 4

En el campo de texto principal introduce el teorema o la prueba que quieres verificar. Puedes escribirlo directamente o pegarlo desde otro editor. El campo acepta cualquier fragmento válido de Lean 4, incluyendo import Mathlib y definiciones auxiliares.

Ejemplo
theorem add_comm' (a b : Nat) : a + b = b + a := by
  induction a with
  | zero      => simp
  | succ n ih => simp [Nat.succ_add, ih]
2 Haz clic en "Verificar"

El botón Verificar envía el código al servidor. El proceso puede tardar unos segundos mientras el kernel de Lean compila el fragmento. Un indicador de carga aparece durante la espera.

3 Interpreta el resultado

El panel de resultado muestra uno de los siguientes estados:

Válida El código compiló sin errores. La demostración es formalmente correcta.
Con errores Lean reportó uno o más errores. El detalle aparece en el bloque de mensajes del compilador, con número de línea y descripción del problema.
Con advertencias El código compiló pero Lean emitió advertencias (por ejemplo, sorries o axiomas adicionales). La prueba se acepta con observaciones.
Consejos útiles
  • Si el código depende de Mathlib, asegúrate de incluir import Mathlib al inicio del fragmento.
  • Los errores de tipo "unknown identifier" suelen indicar que falta un import o que el nombre está escrito de forma distinta a la definición en Mathlib.
  • El botón Limpiar borra el código y el resultado para empezar una nueva verificación desde cero.

Preguntas frecuentes

¿Cuánto tiempo tarda la verificación?
Normalmente entre 5 y 30 segundos, dependiendo de la complejidad del código y del número de imports. Fragmentos con import Mathlib completo pueden tardar más la primera vez por la carga del entorno.
¿Puedo verificar múltiples teoremas a la vez?
Si. Puedes incluir varios theorem, lemma o def en el mismo fragmento. Lean los compilará en orden y reportará errores en cada uno de forma independiente.
¿Los resultados se guardan?
Las verificaciones realizadas desde la pestaña independiente no se almacenan. Si trabajas dentro de un proyecto en el Workspace, los nodos de verificación sí quedan registrados en el grafo del proyecto.

Traducción de Demostraciones

La pestaña Traducir a Lean permite convertir enunciados matemáticos escritos en lenguaje natural a código Lean 4 verificado, o bien traducir código Lean 4 a una descripción en lenguaje natural. El proceso usa un modelo de lenguaje (LLM) y verifica automáticamente el código generado con el compilador de Lean.

1 Configura el modelo y la clave de API

Haz clic en el botón Configuración (parte superior de la página) para desplegar el panel de ajustes. Ahí encontraras:

Modelo LLM Selecciona el proveedor y modelo de lenguaje que realizará la traducción. Si la lista está vacía, configura un modelo en Cuenta → IA y Modelos.
API Key Introduce tu clave de OpenRouter (sk-or-…). Solo aparece este campo si has iniciado sesión. La clave se guarda en tu cuenta y no es necesario ingresarla cada vez.
System Prompt Instrucción base que guia al modelo. Puedes dejarla como esta o adaptarla si necesitas un estilo de traducción diferente.
Reintentos max. Número de veces que el sistema volverá a pedirle al modelo una corrección si el código Lean generado no compila. Solo disponible en modo NL → Lean.
2 Elige la dirección de la traducción

El selector central muestra la dirección activa. Usa el botón de intercambio para alternar entre los dos modos:

NL → Lean Escribe un teorema o proposición en español o ingles y el sistema genera el código Lean 4 correspondiente, verificandolo automáticamente.
Lean → NL Pega código Lean 4 y el sistema produce una descripción en lenguaje natural del teorema o la prueba.
3 Modo NL → Lean: escribe el enunciado y traduce

En la primera columna encontraras el campo de entrada. Puedes alternar entre la vista de texto plano (Entrada) y la vista renderizada en LaTeX (Vista LaTeX) para comprobar como queda el enunciado. Una vez listo, haz clic en Traducir a Lean.

Ejemplo de entrada
Para todo natural n, la suma n + 0 es igual a n.

El proceso puede tomar varios segundos. El sistema llama al LLM, obtiene código Lean, lo verifica y, si hay errores, reintenta automáticamente hasta alcanzar el límite de reintentos configurado.

4 Interpreta las columnas de resultado

Al finalizar la traducción se muestran tres columnas:

Código Lean El código Lean 4 final generado. Si el borde es verde, compiló sin errores; si es rojo, el máximo de reintentos se agotó sin exito.
Historial Lista de intentos del LLM. Cada uno muestra el código propuesto y los errores de Lean que lo descartaron. Haz clic en un intento para expandirlo.
5 Modo Lean → NL: pega el código y obtiene la descripción

Cambia la dirección al modo Lean → NL, pega el código Lean 4 en el campo de entrada y haz clic en Traducir a texto. El resultado aparecerá en la columna central como texto en lenguaje natural.

Consejos útiles
  • Escribe el enunciado de forma precisa: incluye cuantificadores (para todo, existe) y el tipo de los objetos (entero, natural, real).
  • Si la traducción falla repetidamente, aumenta el número de reintentos o reformula el enunciado con más detalle.
  • La vista Vista LaTeX renderiza la notación matemática del texto de entrada para que puedas verificar que las expresiones estan bien escritas antes de traducir.
  • La pestaña Traducir a Lean requiere autenticación. Si ves el acceso restringido, inicia sesión desde el menú principal.

Preguntas frecuentes

¿Por qué el botón "Traducir a Lean" está desactivado?
El botón requiere que el campo de texto no este vacío y que haya un modelo seleccionado. Abre el panel de Configuración y elige un modelo LLM.
¿Qué significa que el código sea "inválido" despues de varios intentos?
El LLM generó código Lean pero ninguno de los intentos compiló correctamente. Puedes ver los errores en el historial para entender que parte del enunciado está causando problemas y reformular la entrada.
¿El código Lean generado queda guardado?
Desde la pestaña independiente no se guarda automáticamente. Si trabajas dentro de un proyecto en el Workspace, puedes copiar el código generado y pegarlo en un nodo de traducción del grafo.

Buscar Demostración en Mathlib

La pestaña Buscar Demostración permite recuperar el código fuente Lean 4 de cualquier declaración de Mathlib4, ya sea buscando directamente por su nombre o describiendo el teorema en lenguaje natural para que el sistema sugiera candidatos. El resultado puede enviarse directamente al traductor de NL.

1 Elige el modo de búsqueda

Las pestañas superiores permiten cambiar entre los dos modos disponibles:

Por nombre Introduce el nombre exacto de la declaración en Mathlib4 (por ejemplo Nat.succ_pos, Real.sqrt_sq) y el sistema recupera su código fuente directamente. Este modo no requiere autenticación.
Por lenguaje natural Describe el teorema en texto libre y el modelo sugiere una lista de nombres de declaraciones en Mathlib4 que podrían coincidir. Requiere iniciar sesión y tener un modelo LLM configurado.
2 Modo "Por nombre": busca la declaración

Escribe el nombre exacto de la declaración en el campo de texto y haz clic en Buscar. El nombre debe coincidir con el identificador de Mathlib4, respetando mayusculas, puntos y guiones bajos.

Ejemplos de nombres válidos
Nat.succ_pos
Real.sqrt_sq
Finset.sum_comm
List.length_append
3 Modo "Por lenguaje natural": obtiene sugerencias

Escribe una descripción del teorema en el área de texto y haz clic en Buscar Sugerencias. El sistema usa el modelo LLM configurado para generar una lista de candidatos. Haz clic en Cargar .lean junto al candidato que desees para recuperar su código fuente.

Ejemplo de descripción
The successor of any natural number is positive

Para usar este modo debes haber iniciado sesión y tener un modelo LLM seleccionado en el panel de Configuración del modelo.

4 Interpreta el resultado y traduce a NL

Cuando se encuentra la declaración, su código fuente Lean 4 aparece en un bloque de código debajo. Si iniciaste sesión y tienes un modelo configurado, el botón Traducir a NL (.tex) envía ese código al traductor Lean → NL y produce una descripción en lenguaje natural lista para copiar.

Encontrada Se muestra el código Lean 4 de la declaración con nombre y tiempo de consulta.
No encontrada El nombre no existe en Mathlib o el worker de Lean no pudo resolverlo. Verifica la ortografia exacta del identificador.
Consejos útiles
  • Los nombres en Mathlib4 son sensibles a mayusculas y minusculas: nat.succ_pos no es lo mismo que Nat.succ_pos.
  • Si no recuerdas el nombre exacto, usa el modo de lenguaje natural para obtener sugerencias y luego carga el .lean del candidato correcto.
  • El botón Limpiar borra tanto la entrada como el resultado para iniciar una nueva búsqueda.
  • El modo de lenguaje natural requiere autenticación. Si el botón aparece desactivado, abre Configuración del modelo y selecciona un LLM.

Preguntas frecuentes

¿Qué es Mathlib4?
Mathlib4 es la biblioteca matemática principal del ecosistema Lean 4. Contiene miles de teoremas, definiciones y estructuras algebraicas formalmente verificadas, desde aritmética básica hasta topología y álgebra abstracta.
¿Por qué el modo por nombre dice "no encontrada" si el nombre parece correcto?
Puede ocurrir por tres razones: el nombre tiene una letra en mayuscula o minuscula incorrecta, la declaración existe en Mathlib pero bajo un módulo diferente al esperado, o el worker de Lean tiene una versión de Mathlib que no incluye esa declaración aun.
¿Puedo buscar definiciones o solo teoremas?
El buscador recupera cualquier declaración de Mathlib4: teoremas (theorem), lemas (lemma), definiciones (def) e instancias (instance).

Buscar Linaje de Dependencias

La pestaña Buscar Linaje construye el grafo de dependencias de una declaración de Mathlib4: muestra de qué otros teoremas y definiciones depende, nivel por nivel, hasta la profundidad elegida. Cada nodo del grafo es interactivo y permite consultar el código fuente de la declaración y traducirlo a lenguaje natural.

1 Introduce el nombre y la profundidad

Escribe el nombre exacto de la declaración de Mathlib4 en el campo de texto. A continuacion ajusta el campo Profundidad (valores entre 1 y 4) para controlar cuantos niveles de dependencias se exploraran. Haz clic en Buscar Linaje o presiona Enter para iniciar.

Ejemplo
Nombre:      Nat.exists_infinite_primes
Profundidad: 2

Una profundidad mayor devuelve más nodos pero puede truncarse a 30 si el grafo es demasiado grande. En ese caso aparece un aviso para reducir la profundidad.

2 Navega el grafo interactivo

El resultado se muestra cómo un grafo SVG con los siguientes controles:

Arrastrar nodo Mantén presionado y mueve un nodo para reposicionarlo en el canvas.
Rueda del ratón Acerca o aleja la vista del grafo completo.
Click en nodo Selecciona el nodo y muestra su declaración Lean en el panel lateral.
Reset vista Restaura el zoom y la posición originales del grafo.

Los nodos que no pudieron resolverse en Mathlib aparecen con un estilo diferente (gris o atenuado) e incluyen la etiqueta no encontrado en el panel lateral.

3 Consulta el código fuente de un nodo

Al hacer clic en un nodo, el panel lateral derecho muestra:

Nombre Identificador completo de la declaración y su nivel de profundidad en el grafo.
Código Lean Fuente Lean 4 de la declaración recuperada de Mathlib. Si el nodo aparece como "no encontrado", la fuente no esta disponible en el worker.
4 Traduce la declaración a lenguaje natural (opcional)

Si iniciaste sesión y tienes un modelo LLM configurado en el panel de Configuración del modelo, el botón Traducir a NL (.tex) envía el código del nodo seleccionado al traductor Lean → NL. El resultado aparece renderizado en el propio panel lateral.

Consejos útiles
  • Empieza con profundidad 1 o 2 para tener una visión general rápida. Aumenta la profundidad solo si necesitas rastrear dependencias más profundas.
  • Si el grafo se trunca a 30 nodos, reduce la profundidad o busca directamente una de las dependencias de interés.
  • El panel lateral se puede redimensionar arrastrando la barra divisoria entre el grafo y el panel para ver el código Lean con más comodidad.
  • El botón Limpiar reinicia la búsqueda y borra el grafo actual.

Preguntas frecuentes

¿Qué significa la profundidad del grafo?
La profundidad 1 muestra solo las dependencias directas de la declaración buscada. La profundidad 2 muestra también las dependencias de esas dependencias, y asi sucesivamente. A mayor profundidad, el grafo puede crecer exponencialmente.
¿Por qué algunos nodos aparecen como "no encontrado"?
Algunas declaraciones son axiomas internos, primitivas del kernel de Lean o pertenecen a módulos que el worker no tiene compilados. Aún así se muestran en el grafo para que la estructura de dependencias sea completa.
¿Necesito iniciar sesión para buscar linajes?
No. La búsqueda de linaje y la visualización del grafo están disponibles sin autenticación. Solo necesitas iniciar sesión si quieres traducir una declaración a lenguaje natural desde el panel lateral.

Buscar Proyectos de Formalización

La pestaña Buscar Proyectos permite explorar los proyectos de formalización matemática registrados en la plataforma. Puedes consultar proyectos públicos de cualquier usuario y ver su progreso de verificación, o revisar tus propios proyectos privados si has iniciado sesión.

1 Elige la pestaña: Públicos o Privados

Las dos pestañas superiores dividen la vista en dos modos:

Proyectos Públicos Muestra todos los proyectos marcados como públicos en la plataforma. Disponible sin autenticación.
Mis Proyectos Privados Muestra los proyectos privados en los que participas como autor o colaborador. Requiere iniciar sesión. El botón aparece bloqueado si no estás autenticado.
2 Filtra y selecciona un proyecto

El panel izquierdo muestra la lista de proyectos con un campo de búsqueda para filtrar por nombre. Haz clic en cualquier proyecto de la lista para seleccionarlo y ver su detalle en el panel derecho.

3 Revisa el detalle del proyecto (Públicos)

Al seleccionar un proyecto público, el panel derecho muestra:

Nombre y descripción Titulo, descripción y etiquetas del proyecto.
Colaboradores Autor principal y lista de colaboradores adicionales.
Cobertura de nodos Barra de progreso que indica cuantos nodos del grafo han sido verificados sobre el total de nodos del proyecto.
Cobertura de hojas Barra de progreso específica para los nodos hoja (sin hijos), que representan los objetivos finales del proyecto.

Si has iniciado sesión, aparece el botón + Seguir para suscribirte al proyecto y encontrarlo fácilmente despues. Si ya lo sigues, el botón cambia a Dejar de seguir.

4 Proyectos privados: ver y abrir en Workspace

En la pestaña de proyectos privados, la lista muestra cada proyecto con una insignia que indica si eres Autor o Colaborador. El panel de detalle muestra nombre, descripción y etiquetas. Para acceder al grafo interactivo del proyecto, utiliza la opcion Abrir Workspace desde el menú principal.

Consejos útiles
  • La cobertura de nodos al 100% indica que todos los enunciados del proyecto tienen una demostración formal verificada en Lean 4.
  • La cobertura de hojas es el indicador más representativo del avance real, ya que los nodos hoja son los objetivos que aún no tienen subdemostraciones.
  • Usa el campo de búsqueda para encontrar proyectos por palabra clave en el nombre. La búsqueda es en tiempo real y filtra a medida que escribes.
  • Para crear tu propio proyecto, usa la opcion Crear Proyecto en la sección Workspace del menú principal (requiere autenticación).

Preguntas frecuentes

¿Qué es un nodo hoja en el contexto de un proyecto?
Un nodo hoja es un objetivo de demostración que no tiene sub-objetivos dependientes. Generalmente son los lemas o proposiciones auxiliares más básicos que sustentan el teorema principal del proyecto.
¿Puedo editar un proyecto desde esta pestaña?
No. La pestaña de búsqueda es solo de consulta. Para editar el grafo, agregar nodos o verificar enunciados, abre el proyecto desde Abrir Workspace en el menú principal.
¿Qué diferencia hay entre seguir un proyecto y ser colaborador?
Seguir un proyecto es una marca personal para encontrarlo fácilmente; no otorga permisos de edicion. Ser colaborador significa que el autor te invitó a trabajar en el proyecto y puedes modificar su grafo desde el Workspace.

Crear Nuevo Proyecto de Formalización

La sección Crear Proyecto permite iniciar un nuevo proyecto de formalización matemática. Requiere autenticación. El formulario guia el proceso desde definir el objetivo del teorema hasta confirmar su enunciado y elegir la visibilidad del proyecto.

1 Escribe el nombre del proyecto

El campo Nombre del Proyecto es obligatorio. Elige un nombre descriptivo que identifique el teorema o área matemática que vas a formalizar.

Ejemplo
Fundamentos de la Teoría de Conjuntos
2 Define el objetivo del teorema

El formulario ofrece dos modos para definir el objetivo (goal) del proyecto. Puedes alternar entre ellos con las pestañas Lenguaje Natural y Manual:

Lenguaje Natural Describe el teorema en texto libre (soporta notación LaTeX). Selecciona un modelo LLM y haz clic en Traducir a Lean. El sistema genera automáticamente el goal, los imports y las definiciones auxiliares, y los transfiere a la pestaña Manual.
Manual Escribe directamente el objetivo lógico en Lean 4 (campo obligatorio), los imports de Mathlib necesarios (uno por línea) y las definiciones auxiliares que el goal requiera (ambos opcionales).
Ejemplo — pestaña Manual
Objetivo:  ∀ a b : Nat, a + b = b + a
Imports:   Mathlib.Data.Nat.Basic
Defs:      (vacío)
3 Confirma el enunciado del teorema

En cuanto el campo de objetivo tenga contenido, aparece la sección Confirmar Enunciado del Teorema. Selecciona un modelo LLM y haz clic en Generar vista previa del enunciado. El sistema produce una descripción en lenguaje natural y su renderizado LaTeX para que puedas verificar que el goal captura exactamente el teorema deseado.

Confirmar Si la descripción es correcta, haz clic en "Sí, este es el teorema que quiero probar" para marcar el enunciado como confirmado. El botón Crear Proyecto se habilitará.
Regenerar Si la descripción no es la esperada, usa Regenerar para solicitar una nueva interpretación al modelo, o ajusta el goal en la pestaña Manual y vuelve a generar la vista previa.
4 Completa los campos adicionales y crea el proyecto

Una vez confirmado el enunciado, rellena los campos finales:

Descripción Texto libre opcional que resume el propósito o contexto del proyecto.
Visibilidad Público: cualquier usuario puede ver el proyecto en la sección Buscar Proyectos.
Privado: solo tu y tus colaboradores pueden acceder a el.

Haz clic en Crear Proyecto para finalizar. El botón permanece desactivado si el goal tiene contenido pero no ha sido confirmado. Al crearse correctamente, el sistema muestra un mensaje de confirmación.

Consejos útiles
  • Si usas el modo de lenguaje natural y la traducción falla, aumenta el número de reintentos o reformula la descripción con mayor precisión matemática.
  • La pestaña Vista LaTeX en el campo de descripción NL renderiza la notación matemática para que puedas verificar las expresiones antes de traducir.
  • Si el goal no requiere confirmación (campo vacío), el botón Crear Proyecto se habilita directamente. Sin embargo, se recomienda siempre definir un goal para que el Workspace pueda generar la estructura inicial del grafo.
  • Puedes cambiar la visibilidad de un proyecto despues de crearlo desde la configuración del Workspace.

Preguntas frecuentes

¿Por qué el botón "Crear Proyecto" permanece desactivado?
El botón se desactiva cuando el campo de objetivo tiene contenido pero el enunciado aún no fue confirmado. Completa el paso de confirmación del enunciado o borra el campo de objetivo si no deseas definir un goal inicial.
¿Qué diferencia hay entre el goal, los imports y las definiciones?
El goal es el enunciado Lean 4 que el proyecto busca demostrar. Los imports son los módulos de Mathlib que el goal necesita para compilar. Las definiciones son tipos, funciones o abreviaciones auxiliares que el goal usa pero que no están en Mathlib.
¿Puedo invitar colaboradores al crear el proyecto?
No directamente desde el formulario de creación. Una vez creado el proyecto, los colaboradores pueden ser agregados desde la configuración del Workspace.

Workspace — Vista General

El Workspace es el editor interactivo de proyectos de formalización matemática. Cada proyecto se representa como un grafo de dependencias donde cada nodo es un teorema, lema o resultado que debe ser probado formalmente en Lean 4. Puedes navegar el grafo, seleccionar nodos y aplicar acciones sobre ellos desde el panel lateral. Requiere autenticación.

1Layout de la pantalla

La pantalla se divide en dos zonas principales:

Panel del Grafo Ocupa la parte izquierda. Muestra el grafo SVG con todos los nodos y aristas del proyecto. Tiene controles para hacer zoom (rueda del ratón), desplazar la vista (arrastrar el fondo) y reposicionar nodos (arrastrar un nodo).
Panel Lateral Ocupa la parte derecha. Contiene cinco pestañas: Nodo, TeX, PRs, Defs y Exportar. Se puede redimensionar arrastrando la barra divisoria central.

Ambos paneles pueden ocultarse individualmente con los botones Grafo y Panel de la cabecera. Si ambos estan ocultos, aparece una barra superior para restaurarlos.

2Estados de los nodos

Cada nodo del grafo tiene un estado visual que indica su progreso de formalización:

open El nodo existe pero aún no tiene una prueba formal. Es el estado inicial.
sorry El código Lean compila pero contiene sorry (marcador de prueba incompleta) o tiene errores de compilación.
validated El código Lean compila limpiamente sin errores ni sorrys. La prueba es formalmente correcta.
axiom El resultado fue respaldado por evidencia computacional (nodo de computación) y el PR correspondiente fue aprobado por el autor del proyecto.
3Pestaña Nodo

Al hacer clic en un nodo del grafo, la pestaña Nodo muestra su nombre, estado, tipo y archivo .lean asociado. Desde ahí se accede a la sección Acciones (para nodos de prueba) o Computación (para nodos de computación), y a la sección Resultados con el último resultado de verificación o acción. En la parte inferior aparece el visor del archivo .lean del nodo (solo lectura).

Consejos útiles
  • Usa el botón Reset en la cabecera del grafo para restaurar la posición y zoom originales.
  • El botón Recargar en la cabecera superior sincroniza el grafo y los PRs con el estado más reciente del servidor.
  • Mientras una acción está en curso (verificación, resolver, dividir, computar), todos los botones de acción quedan bloqueados para evitar conflictos.

Workspace — Verificar

La acción Verificar envía el archivo .lean del nodo seleccionado al compilador de Lean 4 y reporta si la prueba es formalmente correcta. Es la acción más directa y no requiere modelo de IA.

1Selecciona el nodo y haz clic en Verificar

Haz clic en cualquier nodo de prueba del grafo (no en un nodo de computación). En la sección Acciones del panel lateral, haz clic en Verificar. El botón muestra un spinner y el texto Verificando… mientras espera la respuesta del servidor.

2Interpreta el resultado

Los posibles resultados aparecen en la sección Resultados:

Exitosa Compilación exitosa y sin sorry. El nodo pasa a estado validated (verde en el grafo). La prueba es formalmente correcta.
Con sorry Compila pero contiene sorry. El nodo pasa a estado sorry. La sección de resultados lista cada sorry con su archivo y línea. Debes completar la prueba y volver a verificar.
Con errores Fallo de compilación. El nodo permanece en estado sorry. La lista de errores muestra cada problema con su número de línea, columna y mensaje del compilador Lean.
3Revisa el archivo .lean del nodo

El visor de .lean (parte inferior de la pestaña Nodo) muestra el código actual del nodo con resaltado de palabras clave de Lean. Puedes usarlo como referencia para identificar los errores antes de corregirlos con la acción Resolver.

Consejos útiles
  • Verificar solo lee el archivo .lean actual del nodo. Si quieres proponer una prueba nueva, usa la acción Resolver.
  • Un nodo validated puede ser reverificado en cualquier momento si sospechas que el estado del repositorio cambió.
  • Los errores de tipo "unknown identifier" suelen indicar que falta un import en el archivo de definiciones del proyecto (Defs).

Workspace — Resolver

La acción Resolver proporciona una prueba formal completa para el teorema del nodo seleccionado. El código Lean enviado es verificado por el compilador y, si es correcto, el sistema genera el archivo .tex del nodo y abre un Pull Request en el repositorio del proyecto para que el autor lo apruebe.

1Haz clic en "Resolver" y elige el modo

Selecciona el nodo y haz clic en el botón Resolver. Aparece un submenú con tres pestañas:

Lenguaje Formal Escribe directamente el código Lean 4 de la prueba en el editor con numeración de lineas.
Lenguaje Natural Describe el enunciado en texto (con soporte LaTeX). La IA lo traduce a Lean 4, verifica el resultado y crea el PR.
IA Automático La IA lee el .tex del nodo, propone una estrategia de prueba, la traduce a Lean 4, la verifica y crea el PR — todo sin intervencion manual. Se puede dar una sugerencia inicial opcional.
2Modo Lenguaje Formal (FL)

Edita el código Lean en el editor. Selecciona un Modelo LLM (obligatorio para generar el .tex del nodo a partir del Lean verificado) y guarda la API key si aún no lo has hecho. Haz clic en Confirmar.

El sistema primero verifica el código Lean con el compilador (~10-20 s). Si compila sin errores, llama al modelo para generar el archivo .tex (~30-120 s). Al finalizar, se crea un PR con los cambios.

3Modo Lenguaje Natural (NL)

Escribe la descripción del enunciado en el área de texto. Puedes alternar entre la vista fuente y la vista renderizada en LaTeX para comprobar la notación. Selecciona el modelo, guarda la key si aplica, y haz clic en Resolver desde NL.

La barra de progreso y el indicador de fase muestran en que etapa se encuentra: Traduciendo NL → Lean, Verificando, Compilación correcta, generando .tex.

4Modo IA Automático

Escribe una sugerencia inicial opcional (estrategia de prueba preferida, lemas a usar, etc.) o dejala en blanco para que la IA proponga libremente. Selecciona el modelo y haz clic en Ejecutar IA Auto.

El pipeline completo es: la IA consulta el .tex del nodo → genera una estrategia en lenguaje natural → traduce la estrategia a Lean 4 → verifica con el compilador → si compila, genera el .tex → crea el PR. Si la verificación falla, el sistema reporta el error sin crear PR.

5Resultado: PR creado

Al completarse exitosamente, se crea un Pull Request en el repositorio del proyecto. El PR contiene los archivos .lean y .tex modificados. Ve a la pestaña PRs del panel lateral para revisarlo y aprobarlo (ver sección PRs y Axiomas de esta guia).

Consejos útiles
  • El modo Lenguaje Formal es el más rápido si ya tienes el código Lean listo. Los modos NL e IA son útiles cuando aún no sabes cómo escribir la prueba.
  • Si el modo NL falla repetidamente, intenta reformular la descripción con mayor precisión matemática o aumenta el número de reintentos en la configuración del traductor.
  • El modo IA Automático es completamente autonomo pero puede tardar varios minutos dependiendo del modelo y la complejidad del teorema.
  • Si el PR ya existe (la prueba no cambio), el sistema reporta "Solve válidado. No hubo cambios" y actualiza el estado del nodo directamente.

Workspace — Dividir

La acción Dividir descompone el teorema de un nodo en sub-objetivos más simples (nodos hijo). El nodo padre recibe un código Lean que lo reduce a los sub-objetivos, y cada hijo se convierte en un nuevo nodo open del grafo que debera ser resuelto de forma independiente. Al igual que Resolver, genera archivos .tex para el padre y todos los hijos, y crea un Pull Request con todos los cambios.

1Haz clic en "Dividir" y elige el modo

Selecciona el nodo y haz clic en Dividir. El submenú tiene las mismas tres pestañas que Resolver: Lenguaje Formal, Lenguaje Natural e IA Automático.

2Modo Lenguaje Formal (FL)

Escribe el código Lean que divide el teorema padre en sub-metas. El código debe compilar correctamente con Lean (sin errores ni sorry). Selecciona el modelo LLM (obligatorio) y haz clic en Confirmar.

El servidor verifica el Lean, genera los .tex del nodo padre y de cada nodo hijo, y crea un PR con todos los archivos. El mensaje de confirmación indica cuantos hijos se crearon.

3Modo Lenguaje Natural (NL)

Describe cómo quieres dividir el teorema. Por ejemplo: qué lemas auxiliares necesitas, o qué casos quieres separar. La IA genera las sub-metas en Lean 4, verifica la estructura de división y crea el PR con el padre e hijos.

Ejemplo de descripción
Divide usando un lema que acota el valor de n
y otro que verifica todos los casos hasta ese límite.
4Modo IA Automático

La IA lee el .tex del nodo, propone por si sola una estrategia de división (con sub-metas concretas), traduce el plan a Lean 4, verifica la estructura y crea el PR. Puedes dar una sugerencia opcional, por ejemplo indicar que tipo de división prefieres.

5Resultado en el grafo

Tras hacer merge del PR (pestaña PRs), el grafo se actualiza: el nodo padre muestra el código de división y los nuevos nodos hijo aparecen con estado open, listos para ser resueltos. El proyecto avanza en profundidad hasta que todos los nodos hoja estén en estado validated o axiom.

Consejos útiles
  • Dividir es útil cuando el teorema principal es demasiado complejo para probarse directamente. Crea una jerarquía de lemas más manejables.
  • En el modo FL, el código Lean debe expresar la reducción del padre a los hijos usando have, suffices u otras tacticas de descomposición.
  • Tras el merge del PR, recarga el workspace con el botón Recargar para ver los nuevos nodos en el grafo.

Workspace — Nodo de Computación

Los nodos de computación son un tipo especial de nodo hijo que respalda un enunciado Lean mediante evidencia numerica o experimental en lugar de una prueba formal pura. Son útiles para propiedades que son difíciles de demostrar formalmente pero pueden verificarse computacionalmente, como rangos de funciones, propiedades estadisticas o resultados de búsqueda exhaustiva. La evidencia puede ejecutarse en el worker local (Python) o en el cluster de computo distribuido (MPI sobre Raspberry Pi).

1Crear un nodo de computación hijo

Selecciona el nodo de prueba al que quieres agregar evidencia computacional. En la sección Acciones haz clic en Nodo Computación. El submenú solicita un modelo LLM (necesario para generar el archivo .tex del nodo hijo). Haz clic en Crear Nodo de Computación.

El sistema crea un nodo hijo de tipo computation en el grafo y genera su archivo .tex. El nuevo nodo aparece en estado open.

2Selecciona el nodo hijo y abre "Ejecutar Computación"

Haz clic en el nodo de computación recien creado en el grafo. En el panel lateral la sección cambia a Computación y aparece el boton Ejecutar Computación. Haz clic en el para abrir el formulario.

El submenú tiene tres pestañas: Lenguaje Formal (formulario manual), Lenguaje Natural (IA genera el payload) e (no disponible IA Auto para compute en este modo).

3Modo Lenguaje Formal: configura el payload manualmente

El formulario tiene los siguientes campos:

Backend Python (worker local): ejecuta el código en el servidor de la plataforma. MPI (cluster RPI): distribuye la computación entre los nodos del cluster Raspberry Pi (2-3 nodos con Slurm + OpenMPI).
Entrypoint Nombre de la función Python que sera invocada. Por defecto run.
Lean Statement Nombre del enunciado Lean que esta evidencia respalda (por defecto GoalDef).
Target JSON Objeto JSON que describe la propiedad a verificar (límites, condiciones esperadas, etc.). Tu función lo recibe como parámetro target.
Input Data JSON Lista o valor JSON de los datos de entrada que tu función debe procesar. Tu función lo recibe como parámetro input_data.
Código Python Implementacion de la función. Debe retornar un diccionario con las claves: evidence (datos de la evidencia), sufficient (bool: True si la evidencia es satisfactoria), summary (texto descriptivo), y opcionalmente records.
Timeout (s) Tiempo máximo de ejecución en segundos (1-900).
Ejemplo de función Python
def run(input_data, target):
    lo, hi = target["lo"], target["hi"]
    records = [{"x": x, "fx": x**2, "ok": lo <= x**2 <= hi}
               for x in (input_data or [])]
    sufficient = bool(records) and all(r["ok"] for r in records)
    return {
        "evidence": records,
        "sufficient": sufficient,
        "summary": f"{len(records)} samples, ok={sufficient}",
        "records": records
    }
4Backend MPI: computación en el cluster

Al seleccionar MPI (cluster RPI), el sistema envía el job al cluster de Raspberry Pi a traves de Slurm. El runner distribuye automáticamente la lista input_data en partes iguales entre los nodos del cluster. Cada nodo ejecuta la función con su porcion local de datos usando la misma firma run(input_data, target), donde input_data es la porcion asignada a ese rango. Los resultados parciales de todos los rangos se combinan en el coordinador antes de evaluar sufficient.

El cluster actualmente tiene 2 nodos de computo activos. Los jobs MPI pueden tardar más que Python local dependiendo de la carga. Usa un timeout generoso (120-300 s) para computaciones distribuidas.

5Modo Lenguaje Natural: la IA genera el payload

Describe el experimento en texto libre. La IA lee la descripción, infiere los campos target, input_data y el código Python, y envía el payload automáticamente. Es útil cuando no tienes claro como estructurar los datos pero si el objetivo del experimento.

Ejemplo de descripción NL
Verificar que f(x) = x² permanece en [0, 1] para x
en [0, 1] usando 100 puntos de muestra uniformes.
6Resultado de la computación

El resultado depende del valor de sufficient devuelto por la función:

sufficient = True La evidencia es satisfactoria. El sistema crea un PR con los resultados. Una vez que el autor del proyecto apruebe el PR (hace merge), el nodo de computación pasa a estado axiom. El enunciado Lean queda respaldado por evidencia empirica en el proyecto.
sufficient = False La evidencia es insuficiente. No se crea PR. El nodo permanece en estado open. Revisa la lógica de tu función o ajusta los parámetros y vuelve a ejecutar.
Consejos útiles
  • La clave de sufficient es que tu función verifique la propiedad real, no simplemente retornar True. El revisor humano (el autor del proyecto) evalua la calidad de la evidencia antes de hacer merge del PR.
  • Para MPI, asegúrate de que input_data sea una lista. El runner la divide automáticamente. Si envias un escalar, todos los rangos reciben el mismo valor.
  • Puedes agregar un modelo LLM opcional para generar un archivo .tex enriquecido con la descripción del experimento. Si no seleccionas modelo, se usa el .tex base del nodo.
  • Usa el campo Timeout con precaución: un timeout muy corto puede cancelar computaciones legítimas en el cluster.

Workspace — Pull Requests y Axiomas

Las acciones Resolver, Dividir y Ejecutar Computación no modifican el repositorio directamente: en su lugar crean un Pull Request (PR) en GitHub con los archivos propuestos. El autor del proyecto revisa el PR y decide si aprobarlo (merge) o descartarlo. Este mecanismo garantiza que todos los cambios en el proyecto pasen por una revisión antes de volverse oficiales.

1Accede a la pestaña PRs

Haz clic en la pestaña PRs del panel lateral. El número junto al nombre indica cuantos PRs estan abiertos actualmente. Cada PR muestra: número, titulo, rama de origen y destino, y autor.

2Inspecciona los archivos del PR

Haz clic en el botón ▼ de un PR para expandirlo y ver sus archivos. Cada archivo muestra:

Nombre y estado Ruta del archivo y si fue agregado, modificado o eliminado.
Diff Lineas agregadas (+) y eliminadas (-) respecto al estado actual del repositorio.
Contenido Para archivos .tex, puedes alternar entre vista de fuente LaTeX y vista renderizada haciendo clic en Renderizado / Fuente.
3Hacer merge (aprobar) un PR

Solo el autor del proyecto (propietario) puede hacer merge. Haz clic en Merge junto al PR. El sistema fusiona los cambios en la rama principal del repositorio y actualiza el grafo del workspace.

Los efectos del merge dependen del tipo de acción que creo el PR:

Resolver El .lean del nodo se actualiza con la prueba propuesta. El nodo pasa a estado validated si la prueba compila limpiamente.
Dividir Se agregan los nodos hijo al grafo con estado open y el padre recibe el código de division. El grafo se actualiza con la nueva estructura.
Computación El nodo de computación pasa a estado axiom. Esto significa que el enunciado Lean asociado queda registrado como respaldado por evidencia empirica en el proyecto. El autor acepta que la evidencia computacional es suficiente para validar la propiedad.
4Descartar un PR

Si el resultado propuesto no es correcto o no es el deseado, haz clic en Descartar. El PR se cierra sin fusionar cambios y desaparece de la lista. El nodo permanece en su estado anterior. Puedes volver a ejecutar la acción con parámetros diferentes para generar un nuevo PR.

Consejos útiles
  • Revisa siempre el contenido del PR antes de hacer merge, especialmente el código Lean, para asegurarte de que la prueba es la esperada y no introduce errores sútiles.
  • Para PRs de computación, evalua la calidad de la evidencia: verifica que el campo evidence contiene datos representativos y que sufficient es True por razones solidas.
  • El botón Abrir junto a cada PR abre el PR directamente en GitHub para una revisión más detallada con el diff completo.
  • Tras hacer merge o descartar, haz clic en Recargar en la cabecera del workspace para refrescar el grafo.
Preguntas frecuentes
¿Qué diferencia hay entre validated y axiom?
Validated significa que existe una prueba formal completa en Lean 4 que el compilador acepta sin errores. Axiom significa que el resultado fue aceptado por el autor del proyecto basado en evidencia computacional (el código retornó sufficient = True y el PR fue aprobado), pero no necesariamente existe una prueba formal en Lean. Los axiomas son útiles para hipótesis experimentales o resultados que son computacionalmente verificables pero formalmente difíciles de probar.
¿Puede un colaborador hacer merge de un PR?
No. Solo el autor (propietario) del proyecto puede hacer merge o descartar PRs desde el workspace. Los colaboradores pueden crear PRs (ejecutando acciones) pero la aprobación final es exclusiva del propietario.

Workspace — Exportar

La pestaña Exportar permite generar una versión ensamblada del proyecto completo: todos los nodos ordenados (hojas primero, raíz al final) en un único archivo .lean verificado, un documento .tex formateado por IA o un PDF listo para compartir.

1Selecciona el modelo para el formato .tex / PDF

El panel Modelo IA para formato .tex / PDF al inicio de la pestaña Exportar requiere un modelo LLM con su API key. El modelo formatea el contenido LaTeX de todos los nodos en un documento estructurado con preámbulo, secciones y entornos de teorema correctos. Es obligatorio para la exportación .tex formateada y el PDF; no se necesita para la exportación Lean.

2Exportar Lean

La exportación Lean ensambla los archivos .lean de todos los nodos en orden (lemas hoja primero, teorema raíz al final) y verifica que el conjunto compila correctamente con Lean 4. El resultado es un archivo .lean descargable con el proyecto completo.

El proceso pasa por las fases: Generando → Verificando. Si hay errores de compilación en el ensamblado, se muestran en la lista de errores.

3Exportar .tex

Genera un documento LaTeX completo usando el modelo IA para dar formato al contenido matemático de todos los nodos. El documento incluye preámbulo, secciones Lemmas y Main Result, y entornos \begin{theorem} / \begin{lemma} con el nombre del teorema Lean en el label.

Puedes descargar el .tex resultante para compilarlo localmente con LaTeX o compartirlo directamente.

4Exportar PDF

La exportación PDF genera primero el .tex formateado y luego lo compila en el servidor para producir un archivo PDF descargable. Requiere el mismo modelo que la exportación .tex.

Consejos útiles
  • Exporta el proyecto Lean primero para verificar que todos los nodos compilan en conjunto antes de generar el documento .tex.
  • Si la exportación Lean reporta errores, revisa que los nodos dependientes estén todos en estado validated o axiom antes de exportar.
  • El orden de exportación (hojas primero, raíz al final) garantiza que los lemas auxiliares estén definidos antes de ser usados en el teorema principal.
